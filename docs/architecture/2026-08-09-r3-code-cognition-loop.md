# R3 代码认知闭环设计

**状态：** Accepted — 维护者已批准 R3 工作包

## 1. 目标

R3 将已有代码、解释和 R1 正交认知数据连接成可往返、可恢复、可复查的阅读闭环。产品结果优先：模型不可用或导航失败时，当前代码、已有解释和用户记录必须保持可读，用户不能因一次异步失败丢失位置。

## 2. 现有基础与迁移决策

- v5 已提供 `user_annotations`、`project_reader_preferences`、`explanation_relationships`，并随文件水合返回标注、项目阅读偏好和关系。
- v6 已提供不含绝对路径和授权的 `reader_resume_state`，保存项目、文件、解释和选择行。
- 解释节点、目标、快照和变化记录已经保存项目、文件、目标、代码哈希与快照标识。

因此 R3 **不新增数据库版本或字段**。本阶段只扩展既有关系 IPC 的只读目标元数据，并在既有事务内更新受影响认知状态。避免无必要迁移，也不改变 v5/v6 的备份、事务、完整性和恢复保证。

## 3. 层级与导航

- 项目层使用持久项目指南说明入口、模块角色和阅读路径。
- 模块层由项目相对目录和项目地图聚合，明确这是结构化项目信息，不伪装成模型生成结论。
- 文件层使用文件解释；函数、代码块、语句、范围和行使用稳定解释目标。
- 层级导航保持当前文件与局部目标；上钻到项目/模块时不删除局部选择，下钻可返回原目标。
- 关系由 `RelatedTarget` 表示。IPC 加法返回目标文件、类型、名称、行范围和状态；旧消费者可忽略新字段。
- 相关跳转先验证项目、文件、授权和目标。只有目标成功加载并验证后才替换当前选择；失败仅给出原因，原文件、解释和选择不变。
- 成功跳转压入有界返回栈；返回同样经过目标验证，失败不弹栈。

## 4. 个人认知与解释深度

- 笔记、问题、风险均是明确标注为“我的记录”的 `UserAnnotation`，不进入模型解释正文。
- 新增、编辑、删除请求绑定项目、文件和解释 ID；迟到结果写回原目标，不覆盖当前目标。
- 通俗/详细是项目级 `ReaderPreference`。切换后保持同一文件、解释、代码版本和导航位置；生成请求携带当前模式。
- 浏览器示例允许内存交互，但明确不持久化；桌面端使用现有 IPC 持久化并在水合时恢复。

## 5. 变化复查

- 变化检测继续只迁移实际受影响的解释。
- 在同一水合事务中，受影响解释对应的 `review_state` 更新为 `needs_review`，revision 递增；旧 `state` 投影在没有 legacy 问题/风险状态时为 `needs_reexplain`。
- 未出现在 `affected_explanation_ids` 中的认知行完全不更新。
- 前端复查队列从当前项目已水合解释的正交认知状态和解释状态派生；处理一项不改变其他项。

## 6. 异步身份

- 模型生成键包含项目 ID、文件 ID、文件哈希、快照 ID、解释 ID、解释代码哈希、上下文 ID、显示模式和请求代次。
- 文件/关系导航绑定当前工作区代次和目标文件/解释；加载完成前不提交选择。
- 标注与偏好响应写入其请求携带的项目/解释，不依赖响应返回时的当前选择。
- 取消同时请求原生取消并使前端代次失效；即使原生请求已完成，迟到结果也无法写回界面。

## 7. 兼容、隐私与回退

- 不删除旧 `ReadingState`、旧 IPC、旧字段或 v5/v6 表；新关系字段均可选。
- 不把源码、提示词、响应、凭据或绝对路径加入诊断、恢复记录或关系载荷；关系只返回内部 ID、相对目标语义和行号。
- 不扩大 renderer 文件系统或网络权限，跨文件导航仍依赖当前原生授权。
- 回退到 R2 时数据库无需降级；旧版本忽略新增 IPC 字段，并继续读取原有 v5/v6 数据。

## 8. 阶段证据

自动化必须覆盖层级模型、关系成功/失败往返、标注与偏好目标绑定、模式生成、受影响复查与未受影响保持、迟到响应、取消、快速项目切换和模型离线已有内容。原生重启、授权恢复和真实项目导航另行记录，不能由单元测试外推。

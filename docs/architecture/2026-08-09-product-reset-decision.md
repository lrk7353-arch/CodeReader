# CodeReader 产品复位决策：重建 AI 代码认知主线

**状态：** Accepted — 维护者已于 2026-08-09 批准产品复位决策

**日期：** 2026-08-09
**影响范围：** 产品定位、信息架构、阅读进度语义、解释交互、公开文档与 1.0 验收优先级

## 1. 背景

CodeReader 最初要解决的不是“如何打开更多文件”，而是 AI 已经降低了写代码的门槛，使用者仍然难以理解、审查、维护并为生成结果负责的问题。最初产品定义中的核心能力是：稳定地把代码与解释映射起来，沿项目结构逐层理解，记录理解状态，并在以后继续阅读。

后续生产化工作补齐了本地优先、安全边界、模型配置、任务状态、诊断、更新、打包和发布证据。这些工作是正式产品不可撤销的基础，但也让产品入口和公共表述逐渐接近“带 AI 的本地文件阅读器”。辅助能力占据了过多一级界面位置，项目认知主线反而没有完整闭环。

本决策不是回滚代码，也不是回到 MVP 质量。它要求保留现有生产契约，同时恢复产品优先级：先把“真正读懂并掌握一个项目”做完整，再扩展文件类型、模型生态或外围工具。

本决策批准后，在产品定位、工作区优先级和 1.0 功能排序上细化并覆盖 `2026-07-10-production-readiness-design.md` 的相关表述；该文档中的安全、隐私、兼容、迁移和发布要求继续有效。

## 2. 产品北极星

### 2.1 一句话定义

CodeReader 是一款本地优先的 AI 代码认知桌面工具，帮助 AI 时代的代码使用者沿着可恢复的阅读路径，从项目全貌进入具体代码，理解其作用、关系与风险，并持续保存自己真正掌握了什么。

对外的简短表达为：

> AI 写代码，CodeReader 帮你真正读懂并掌握代码。

### 2.2 首要用户

首要用户是拥有或接手了一个可运行代码项目、但尚未形成完整心智模型的人，尤其包括：

- 使用 AI 生成代码的初学者、独立开发者和非传统技术创作者；
- 需要审查外部或 AI 生成项目的产品负责人和创业者；
- 需要快速进入陌生代码库的学习者与开发者。

专业开发者仍然受益，但 1.0 不以替代 IDE、代码编辑器或通用智能体为目标。

### 2.3 核心用户任务

用户离开 CodeReader 时，应能回答五个问题：

1. 这个项目解决什么问题，如何运行？
2. 它由哪些关键模块组成，模块之间如何连接？
3. 当前代码在局部和整个项目中分别起什么作用？
4. 哪些部分重要、危险、未知或需要复查？
5. 我已经理解了什么，下一步最值得读什么？

## 3. 产品主线

唯一一级主流程为：

> 打开项目 → 建立项目地图 → 获得推荐阅读路径 → 查看代码与解释 → 记录理解、问题和风险 → 跳转相关代码 → 项目变化后识别影响 → 下次从原处继续

单文件打开、文本和 Markdown 阅读继续受支持，但它们是兼容入口，不再定义产品首页、导航结构或主要成功指标。

## 4. 核心产品对象

### 4.1 项目认知地图

展示入口、关键模块、数据流、控制流和模块关系。它不是完整文件树的替代品，而是回答“先看哪里、为什么”的认知索引。

### 4.2 阅读路径

由有顺序、有理由的认知节点组成。节点可以指向项目、模块、文件、函数、代码块或行。路径需要支持暂停、继续、跳过、复查和重新排序，但不得把推荐顺序伪装成唯一正确顺序。

### 4.3 解释目标

解释必须明确作用域，并至少覆盖：

- 这段代码做什么；
- 它在局部和项目中的作用；
- 前置知识或依赖；
- 相关代码和可导航关系；
- 风险、假设与审查建议；
- 解释的来源、状态和是否可能过期。

用户可以在通俗模式与详细模式之间切换。项目级、模块级、文件级和局部代码解释必须形成可上钻、下钻的连续层级。

### 4.4 理解记录

理解记录属于用户，而不是模型。它包括理解状态、个人笔记、待解决问题、风险标记、最后阅读位置和解释版本。重新打开项目后必须可恢复；项目变化后不得静默沿用已经失真的结论。

### 4.5 变化影响

当文件或解释依据发生变化时，系统应指出哪些解释、节点和理解记录可能受影响，并允许用户复查。陈旧后台工作不得覆盖当前项目、当前文件或当前选择。

## 5. 信息架构决策

### 5.1 工作区

桌面宽度允许时，默认工作区保持三栏认知模型：

- 左侧回答“接下来读什么”：项目地图、阅读路径和理解进度；
- 中间回答“代码究竟是什么”：真实源码、稳定定位和选择范围；
- 右侧回答“它为什么重要”：分层解释、关系、风险、笔记与问题。

窄窗口必须提供清楚的面板切换与当前上下文提示，不能简单把解释推到首屏以下。键盘操作、焦点顺序、可见焦点、语义标签、缩放和对比度是该结构的验收条件。

### 5.2 顶栏

顶栏只保留高频、跨工作区操作：

- 打开项目；
- 继续上次阅读；
- 当前模型健康状态；
- 当前后台任务状态；
- 一个紧凑的更多菜单。

打开单文件可以保留为次级入口。模型详细配置、提示词注册表、反馈包、更新和发布信息进入设置、任务中心或更多菜单，不再与主流程竞争一级注意力。

### 5.3 起始页

起始页首先呈现“继续最近项目”“打开项目”和一个可验证的示例项目。它需要解释 CodeReader 将帮助用户得到什么，而不是罗列技术能力和设置入口。

## 6. 进度语义

产品只展示一个一级进度：**关键阅读路径掌握度**。

其分母是当前路径中需要掌握的节点，分子是用户明确标记为已理解的节点。文件访问、模型已生成解释、路径节点完成和用户已理解是不同事件，不得复用同一文案或百分比。

文件、模块和整个项目可以展示局部统计，但必须标注作用域和计算口径。相同状态在顶栏、路径、文件树和解释面板中的表达必须一致。现有数据应通过兼容映射或可重算派生值迁移，不得破坏旧版本中的阅读记录。

## 7. 能力分层

### 7.1 前台核心

- 项目打开、最近项目与继续阅读；
- 项目地图和推荐阅读路径；
- 代码与解释的稳定映射；
- 项目、模块、文件和局部代码的分层解释；
- 相关代码跳转；
- 理解状态、笔记、问题与风险；
- 解释持久化、恢复与陈旧提示；
- 统一且可解释的掌握度。

### 7.2 生产支撑

- 模型配置与凭据引用；
- 任务队列、取消、重试和恢复；
- 更新、反馈包与诊断；
- 文本、Markdown、图片等既有兼容阅读能力；
- 数据库迁移、隐私清理、安装与卸载、包验证。

这些能力继续维护，但默认不占据主流程的视觉中心。

### 7.3 复位完成前冻结

- 新文件格式扩张；
- 新模型供应商或模型市场；
- 通用聊天入口；
- 代码编辑、生成或智能体执行；
- 团队协作与云同步；
- 仅为品牌新鲜感进行的更名或视觉重做。

安全修复、兼容性修复和发布阻断修复不受冻结影响。

## 8. 不可退让的生产契约

复位不得削弱以下既有要求：

- Windows 与 Linux 的 x64/ARM64 1.0 支持矩阵；
- 仅由原生选择器授权用户选择的文件或目录，渲染器不获得任意文件系统或网络权限；
- `0.10.x` 与 `0.11.x` 的解释、进度、提示词、模型配置和凭据引用兼容性；
- 数据迁移前备份、事务变更、完整性检查和非破坏恢复路径；
- 导出诊断中不包含源码、提示词、模型响应、凭据和个人绝对路径；
- 所有后台工作绑定目标，陈旧结果不得替换当前文档或状态；
- 发布前完成原生包冒烟、校验和、SPDX SBOM 与制品证明；
- 未通过 Authenticode 验证时不得宣称 Windows 包已签名。

如实现复位必须改变其中任何一项，需要单独的架构决策和维护者批准。

## 9. 成功判据

复位后的产品至少满足：

- 新用户可以在不先配置外围功能的情况下，从项目进入第一条有意义的解释；
- 用户能从项目全貌下钻到具体代码，并从局部解释返回项目关系；
- 所有界面对“已读、已解释、已理解、需复查”的含义一致；
- 用户可以留下自己的笔记和问题，并在重启后恢复；
- 代码变化能触发可见、可定位、可处理的陈旧状态；
- 在支持的窄窗口和键盘路径中，代码与解释仍可连续切换和关联；
- 公共 README、安装说明、版本历史、发布说明和应用内文案使用同一产品定义。

定量目标和验证方法由配套实施计划管理。未经真实项目验证，不得以单元测试通过宣称复位完成。

## 10. 被否决的替代方案

### 重写产品

现有安全、持久化、任务、打包和兼容基础具有生产价值。重写会放大迁移和发布风险，不能解决优先级失焦。

### 删除所有生产支撑能力

这些能力不是偏航本身；问题在于它们侵占了主流程。删除会使产品重新退化成演示品。

### 只做视觉精简或更名

当前问题包含进度语义、认知层级、用户记录和变化影响的功能缺口。换皮不能恢复产品闭环。

### 继续扩展为通用阅读器

这会进一步稀释差异化，也无法直接回答用户是否真正掌握了一个代码项目。

## 11. 后果与批准

正面后果是产品重新拥有清楚的主任务、界面层级和完成定义；生产基础不再与核心体验竞争，而是支撑它。代价是部分已经可见的入口需要降级，短期新增能力受限，进度与持久化模型可能需要兼容迁移。

维护者批准本决策后，按 `docs/plans/2026-08-09-product-reset-plan.md` 执行。复位结束不等于 1.0 可以公开发布；完整发布矩阵和证据仍需独立通过。
